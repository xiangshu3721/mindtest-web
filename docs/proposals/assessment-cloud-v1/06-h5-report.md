# 06 · H5 报告链接

## 1. 链接长什么样

```text
https://xiangshu3721.github.io/mindtest-web/r/#rpt_<id>.<linkSecret>
```

- 页面是合集站上的静态文件 `r/index.html`，与各测评页共存，不替换首页。
- `reportId` 与 `linkSecret` 放在 hash 里。GitHub Pages 看不到 hash，静态托管日志里也不会有秘密。
- 页面脚本取出 hash，再 `POST /v1/results/read`。作答者的 localStorage 不参与读取。换手机、微信内置浏览器，只要链接完整就能开。
- 不使用爱的 5 种语言那种 `?r=分数` 形式。

作废口令不放进这条链接。它只留在交卷那台设备。

## 2. 页面行为

`r/index.html` 是一个薄壳，不是 18 套题的复制。

1. hash 缺失或格式不对：显示「链接不完整」，无重试刷库。
2. 请求中：显示测评名占位，不先画假分数。
3. 200：按 `assessmentId` 选择只读渲染器，画 `reportContent`。页脚写昵称、完成时间、规则版本、非诊断声明（声明文本来自该测评原来的页面，随协议保存，不在报告站新写一套临床结论）。
4. 410：显示「这条链接已经失效」，不显示分数残片。
5. 404 / 网络失败：显示「打不开」，提供「再试一次」。不把失败缓存成空报告。
6. 无登录框、无手机号、无「注册后查看」。

微信里点右上角分享，分享出去的仍是同一条 hash 链接。接收者打开后同样走读接口。

## 3. 微信卡片标题的限制

GitHub Pages 的 `index.html` 是静态的，微信抓取分享卡片时**不会**执行这段脚本，因此卡片标题只能是 `r/index.html` 里写死的一句，例如「ASVA 测评报告」，不能变成「小林的霍兰德报告」。

第一期接受这件事。不要为了卡片标题把 linkSecret 放到查询串，那会让秘密进入微信服务器日志。

若以后一定要个性化标题，再单独做 CloudBase 的 HTML 响应，并只在查询串放 reportId、秘密仍走一次跳转后的 hash。那是后续项，不在第一期。

## 4. 渲染器与测评页的关系

渲染器读取协议，调用**已经存在**的展示规则，不新算分数。

| 阶段 | 渲染策略 |
|---|---|
| 第一期 六芒星 | 报告页内用少量模板画倒三角词与正三角词。数据只来自 `dimensions[].labels` 与 viewModel |
| 第二期 结构简单的测评 | 巨婴、5 种语言、SEFS、ECR：条形与类型名。ECR 点图用两个均分重算坐标，公式与 `ecr/js/app.js` 里现有的 `((mean-1)/6)*100` 相同，不算新算法 |
| 第三期 | 珍爱文字报告 + 雷达；霍兰德复用其 `report.js` 的选句（把该文件以只读方式引入或原样拷贝到报告页，版本号必须与 `assessmentVersion` 锁定）；个人充电展示已保存的 compute 结果，不在报告页调用「按第几天轮换」 |
| 第四期 | SCL-90、PDQ-4、Beattie、心力地图。优先画 interpretation 段落与维度表。SCL-90 危机块用醒目样式，文案仍是原 `crisis.text` |
| 寻根 | 只渲染地图快照文本。不提供档案编辑 |

做不到像素级一致时，页面顶部写「这是同一份结果的阅读页，交互图表以原测评页为准」。`compat.gaps` 列出来。不允许用截图 OCR 填空。

原测评页的「导出图片」保留。H5 不替代 PNG。

## 5. 与作答页的衔接

交卷并展示结果之后，结果页底部增加一块，默认折叠或放在导出按钮旁，避免挡住原报告：

- 复选框，默认不勾选。
- 勾选后按钮「生成报告链接」。
- 成功：显示链接、复制、本机「使链接失效」。
- 失败：显示「再试一次」，结果区不变。

深链打开测评、刷新恢复进度，都不自动上传。

微信内打开测评页时，localStorage 可用则队列能重试；不可用则只在当次页面成功或失败，不新造登录。

## 6. 安全预期（写进给导师的说明）

链接等同于报告密码。转发到群，群成员都能看。撤销前已经打开并截图的内容收不回。报告页禁止被搜索引擎索引：`r/index.html` 加 `noindex`，且正文由接口返回，静态 HTML 里没有分数。

不要把报告页做成目录站的一张新卡片。
