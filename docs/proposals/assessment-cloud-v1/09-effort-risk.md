# 09 · 工作量口径与风险

不估日历工期。用改动面说明「做完第一期」和「做完全系列」差在哪。

## 1. 工作量按块，而不是按测评平均分

| 块 | 包含 | 依赖 | 规模 |
|---|---|---|---|
| A. 确认 | README 文末 7 项：飞书应用、Base、全文放哪、试点测评、寻根边界、打开链接的文案、谁有权在 ASVA 粘贴 | 无代码 | 决定后面会不会推倒 |
| B. 云函数与索引 | schema 校验、文档库、飞书索引写入、提交/读取/撤销、日志脱敏、限流 | A | 一份后端。与测评套数无关，是全系列的共同成本 |
| C. cloud-kit + 报告壳 | 同意、队列、链接、失效页 | B | 一份前端共享。第一期只做六芒星模板 |
| D. 单套挂点 | 08 表里的一个 save 点，抓原对象 | C | 站内一套通常是一个函数；Beattie 还要重新构建；站外仓要单独发布 |
| E. 只读渲染 | 让 H5 看起来像原报告 | D 的数据已经是 full | 六芒星小；SCL-90 / 珍爱 3D / 心力地图大 |
| F. ASVA 粘贴 | 预览、SourceRecord、去重、Staging | B，且工作台发布纪律 | 与测评渲染无关，可在 D 的第一套之后并行 |

全系列不是 18 倍的 B。贵的是 B、C、F 各一次，加上每套 D/E。临床套件的 E 和同意文案比六芒星重，不是因为题多，而是因为危机句、姓名和「不能改算法却要像素级复述」。

寻根之旅若要从 partial 升级到整包归档，工作量接近另一套产品（脱敏、手机号、权限），不要算进测评 V1。

## 2. 风险

| 风险 | 实勘依据 | 控制 |
|---|---|---|
| 用历史摘要上云，导师看到残缺报告 | result-kit `clean()` 截断；巨婴 notes 只留 5 条高分；心力地图历史去掉自述 | 只在交卷内存抓原对象。摘要仅作 textFallback |
| 密钥进前端 | 小调查 `submit.js` 留有直连 token 的代码路径，config 注释已警告 | 测评不复制该路径。审查时搜索 `appSecret`、`tenant_access_token` |
| 公开 webhook 被刷 | 小调查 webhook URL 已在公开仓库 | 测评使用自有函数与限流，不复用该 URL |
| 两个飞书应用搞混 | `cli_aa3e5840a3f89d2b` 未出现在读过的源码；ASVA 使用环境变量中的另一套配置 | 确认前不建表 |
| 同源 localStorage 串数据 | 所有 `github.io` 子路径共享 origin | 新键使用 `rk.cloud.*`，不复用 `rk.v1.<id>` 存全文队列以外的结构；队列与历史分开 |
| 霍兰德昵称与合集站昵称不一致 | 霍兰德用 `holland_explore.nick` | 上云时以该页输入框为准，不悄悄改用另一套昵称 |
| 5 种语言短链被当成秘密 | `?r=` 可枚举 | 报告 hash 使用随机 linkSecret |
| 寻根误传手机号 | `BasicProfile.phone` 在 IndexedDB 档案 | 默认 partial；代码审查清单包含「请求体不得含 phone / wechatQr」 |
| SCL-90 姓名与危机内容扩散 | 资料页姓名进 `who`；第 15 题有危机文案 | 单独同意；预览列不放危机全文；报告页保留原文 |
| 撤销后档案里仍有文字 | 导入写入的是 SourceRecord 副本 | 导入前说明。撤销只杀链接 |
| 规则以后改了，旧报告变了 | 若 H5 现场重算就会变 | 保存 score 原对象与 assessmentVersion，禁止云端重算 |
| 站外 result-kit 副本不一致 | 各仓自带一份 | 不依赖改 result-kit 来上云 |
| 微信分享卡片不显示姓名 | Pages 静态 HTML | 第一期接受，见 06 |
| 清浏览器后不能自助撤销 | ownerToken 只存本机 | 文案写明；管理员可在索引表把状态改为已撤销 |
| ASVA 生产误写入 | 该仓要求 Staging 与生产写保护 | 导入先上 Staging |
| 调试预填被上传 | SCL-90 `?debug`、PDQ `?preview`、ECR `?debug` | cloud-kit 见到这些查询参数就不渲染上传 |
| 飞书长文本截断 | 全文若只存表 | 权威数据在 CloudBase，表只存索引 |
| Beattie 只重建了源码没提交产物 | 线上跑的是 `beattie/assets` | 清单要求源码与产物一起发 |
| 跨测评排行榜被做成产品 | 分数方向相反（心力地图高=困扰多，珍爱高=更稳） | 飞书不设「总榜」视图 |

## 3. 不做的事

- 不重写 13 张卡片的 UI。
- 不上手机号登录或微信 OAuth。
- 不把结果提交进 GitHub Issues、Gist 或仓库 JSON。
- 不让 AI 在导入时自动改客户事实。
- 不在第一期搬珍爱三维交互和寻根编辑器。
