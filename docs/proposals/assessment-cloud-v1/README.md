## 实勘结论（先看这 8 条）

1. 线上合集站 `index.html` 现为 **13 张卡片**。站内可运行测评是 SCL-90、PDQ-4、ECR、情绪健康测试（内含 6 套）、职业六芒星。其余 8 张是独立 GitHub Pages，公开仓库均已读到。
2. `mindtest-web` 内 **没有** CloudBase、飞书、webhook。云端痕迹在别的仓库：问己与 ASVA 工作台共用 CloudBase 环境 `root-journey-prod-d4d7pzd0a8f805`；生活与心情小调查用妙搭 webhook 写飞书；寻根之旅用腾讯云函数代理 DeepSeek，档案仍在浏览器。
3. 多数测评已有昵称门槛（`rk.v1.nickname`，1–12 字，全站 `xiangshu3721.github.io` 同源共享）和本机历史。**没有任何测评有可撤销的云端报告链接。** 爱的 5 种语言有 `?r=` 分数链接，分数空间可枚举，不能当作 reportId。
4. SCL-90 / PDQ-4 / ECR 的完整分数对象只活在当次 `sessionStorage`；`localStorage` 里的 result-kit 摘要会被截断（标题 120 字、说明 260 字、指标最多 16 条、提示最多 6 条）。上云必须在交卷当时取计分原对象，不能事后读历史摘要。
5. 珍爱金字塔已经用 `ResultKit.save(summary, { data })` 把 36 题答案放进历史，这是站内最接近「可重绘」的写法，后续适配优先对齐它，而不是对齐妙搭公网 webhook。
6. 飞书应用号 `cli_aa3e5840a3f89d2b` **没有**出现在本次读到的前端文件里。小调查配置里的 webhook 地址是公开的，且注释写明不要把高权限密钥放进静态页。新方案不要复制「浏览器直连带密钥的飞书」。
7. ASVA 工作台（`asva-workbench`，默认分支 `master`）已有客户档案、原始资料 `SourceRecord`、证据与「确认后才写入」的规则。测评结果应作为一条原始资料导入，**不要新建第二套客户主表，也不要让测评分数直接改客户字段。**
8. 寻根之旅含手机号、父母传记和 AI 洞察，不能按普通 30 题量表整包上传。EAP 目录是静态讲义，不是测评。

## 必须遵守的 12 条

| # | 约束 | 方案落点 |
|---|---|---|
| 1 | 不重写测评、不改交互主路径 | 只在交卷成功之后加可选同意与提交 |
| 2 | 不改评分算法与文案规则 | 原样保存计分函数返回值 |
| 3 | 密钥不出前端 | 飞书 `tenant_access_token`、应用密钥只放 CloudBase 环境变量 |
| 4 | 结果不进 GitHub 仓库 | 不写 issues、不写仓库文件、不把 JSON 提交进 git |
| 5 | 每份结果独立 `reportId` | 客户端生成 `rpt_` + 随机串，链接不依赖 localStorage |
| 6 | 先知情同意再上传 | 未勾选则只留本机；同意文案带版本号 |
| 7 | 分享权限可区分 | 打开报告只凭链接能力；ASVA 导入还要服务端集成密钥 + 链接秘密 |
| 8 | 链接可撤销 | 作答者本机持有作废口令；作废后 H5 与导入都读到失效 |
| 9 | 防重复提交 | `clientSubmissionId` 与 `reportId` 唯一，重试是更新同一条 |
| 10 | 失败可重试，且不挡住看结果 | 本机待发队列；页面照常显示本次结果 |
| 11 | 无手机号登录 | 昵称即称呼；不引入账号体系 |
| 12 | 与现有 GitHub Pages 共存、低成本 | 页面仍放 Pages；读写走已有 CloudBase 环境上的新函数，不另起一套云 |
